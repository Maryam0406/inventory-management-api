# Inventory Management API — PostgreSQL Edition

A REST API for managing inventory items, built with Node.js, Express, and PostgreSQL (via Drizzle ORM). This is the database-integrated evolution of the original in-memory Inventory Management API, built for Codveda Technology's Full-Stack Development Internship — Level 2, Task 3 (Database Integration).

> This branch (`feature/postgresql-database`) contains the database-backed version. See the `main` branch for the original in-memory (Level 1) version.

## What changed from the in-memory version

- Data is now stored in a real PostgreSQL database instead of a JavaScript array — it persists across server restarts.
- IDs are auto-generated by PostgreSQL (`serial`), not manually tracked.
- Duplicate-SKU and not-found checks now query the database directly.
- Prices are stored using PostgreSQL's `numeric` type (not floating-point) to avoid rounding errors in money calculations.
- Schema changes are tracked and applied through Drizzle migrations, giving a trackable history of the database's structure over time.

## Tech stack

- Node.js + Express
- PostgreSQL
- Drizzle ORM + drizzle-kit (migrations)
- `pg` (PostgreSQL driver) + connection pooling
- `dotenv` for environment configuration

## Getting started

**1. Install dependencies**
```bash
npm install
```

**2. Set up PostgreSQL**

Make sure PostgreSQL is installed and running locally, and create a database:
```sql
CREATE DATABASE stockly_inventory;
```
(Can also be done via pgAdmin: right-click **Databases** → **Create** → **Database**.)

**3. Configure your connection string**

Create a `.env` file in the project root:
```
DATABASE_URL="postgresql://postgres:YOUR_PASSWORD@localhost:5432/stockly_inventory"
```
`.env` is gitignored — never commit real credentials.

**4. Run the migration** (creates the `items` table)
```bash
npx drizzle-kit generate
npx drizzle-kit migrate
```

**5. Start the server**
```bash
npm run dev     # with nodemon (auto-restart)
# or
npm start       # plain node
```

Server runs at `http://localhost:5000`.

## Data model

Defined in `db/schema.js`:

| Field                | Type                        | Notes                                            |
|----------------------|------------------------------|---------------------------------------------------|
| `id`                 | serial, primary key          | Auto-generated by PostgreSQL                       |
| `name`                | varchar(255), not null       |                                                     |
| `sku`                 | varchar(100), not null, unique | Enforced unique at the database level             |
| `category`            | varchar(100), not null       | Defaults to `"Uncategorized"`                      |
| `quantity`            | integer, not null            |                                                     |
| `price`               | numeric(10,2), not null      | Stored as a string on insert/update for precision   |
| `low_stock_threshold` | integer, not null            | Defaults to `5`                                    |

## Endpoints

Same routes and behavior as the original API — see the `main` branch's README for full request/response examples.

| Method | URL                       | Description                                  |
|--------|---------------------------|-----------------------------------------------|
| GET    | `/`                        | Health check                                   |
| GET    | `/api/items`                | Get all items                                   |
| GET    | `/api/items/low-stock`      | Get items at/below their low-stock threshold    |
| GET    | `/api/items/:id`            | Get one item                                    |
| POST   | `/api/items`                 | Create an item                                  |
| PUT    | `/api/items/:id`             | Update an item (partial updates supported)      |
| DELETE | `/api/items/:id`             | Delete an item                                  |

## Verifying persistence

To confirm data is genuinely stored in the database (not memory):
1. Create an item via `POST /api/items`
2. Stop the server (`Ctrl+C`)
3. Restart it (`npm run dev`)
4. `GET /api/items` — the item is still there
